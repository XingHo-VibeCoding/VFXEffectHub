# Day 11｜详情页加有反馈的交互（复制来源链接）

## 任务
- 板块 ①：交互反馈原理（每日一问答案：反馈应发生在用户视线焦点——按钮自身变化优于邻近提示优于 toast）
- 板块 ②：实现「复制来源链接」交互
- 板块 ③：连续操作测试（成功 / 再次操作 / 失败）

## 选定交互
**「📋 复制来源链接」**：详情页「查看来源 ↗」链接旁新增按钮。
- 不依赖后端，纯前端 Clipboard API
- 不触碰 Day 7 已有的点赞/收藏/加入收藏夹（保持不变的功能）
- 覆盖四要求：成功反馈 / 再次操作 / 防重复 / 失败提示

## 状态变化
| 阶段 | 按钮 | 提示 | 类型 |
|---|---|---|---|
| 初始 | 📋 复制链接 | 无 | — |
| 处理中 | 复制中…（disabled） | 无 | — |
| 成功 | ✓ 已复制（1.5s 恢复） | 已复制到剪贴板（绿） | ok |
| 失败 | 恢复初始 | 复制失败，请手动选中下方链接复制（红） | error |

## 改动文件
- `js/detail.js`：render 里「查看来源」链接改为 `.detail-source-row` 包裹 + 复制按钮 + `#copyMsg` 提示位；bindActions 加复制逻辑（disabled 防重复、Clipboard API、成功/失败分支、1.5s 自动恢复）
- `css/style.css`：新增 `.detail-source-row`（flex 并排）、`.copy-btn--ok`（成功绿边框）、`.fav-msg--ok`/`.fav-msg--error`（绿/红提示）
- `detail.html` 不动（按钮由 JS 动态生成）

## 验证（板块 ③ 测试结果）
1. 成功：✅ 用户实测通过（按钮变 ✓ 已复制 + 绿字，粘贴是 URL）
2. 再次操作：功能上用户觉得「没必要」——已解释：今日清单明确要求「处理期间按钮不可重复点击」，锁按钮保留；复制是瞬时操作所以感知弱，第 3 周接真实网络请求后该模式才有体感
3. 失败：file:// 打开详情页整页就「加载失败：Failed to fetch」（fetch 需 http，规则 B），到不了复制按钮 → 改用 Console 注入 `Object.defineProperty(navigator, 'clipboard', { value: undefined })` 模拟 Clipboard API 缺失来触发失败红字
