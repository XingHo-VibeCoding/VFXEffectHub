# research.md — 游戏特效素材参考收集网站（VFXEffectHub）

## 项目

- **项目名**：VFXEffectHub
- **研究日期**：2026-09-18（Day 3）
- **作者**：零基础学习者
- **一句话定位**：为游戏特效制作者汇集分散的游戏特效素材；网站按 **视频 / 贴图** 两大素材形态分区；用户用**搜索框输入任意标签关键词**找到参考，**标签完全自定义**（不预设字典——用户写「刀光」「鸣潮」「UE」都可以）；用户还可以为自己建**自定义收藏夹**管理内容

## 1. 研究方法

实际抓取三个同类产品的页面，记录页面结构、主要数据、用户动作；用经验补充抓不到的部分并明确标注「待核实」。

三个对比对象的选择理由：

| 产品 | 选择理由 |
|---|---|
| **魔法盒（magesbox.com）** | 直接对标游戏特效 |
| **哔哩哔哩（bilibili.com）** | 视频形式代表，与瀑布流代表对比 |
| **花瓣网（huaban.com）** | 瀑布流 + 采集范式代表 |

### 2.4 优点

**魔法盒**
- 直接对标游戏特效，引擎分类专业
- 评论是真正的特效师，技术讨论深（例：「顶点偏移的强度用曲线线控」）

**哔哩哔哩**
- 内容量大、教程多
- **视频形式更直观** —— 特效是动态的，视频比静态图更能看清真实效果
- 求职作品集本身有参考价值（能看同期水平与手法）

**花瓣网**
- 瀑布流体验流畅、采集功能好用
- **是游戏特效师「去那找参考」的目的地之一** —— 上面有部分特效贴图（序列帧、静帧分解图、材质参考等）。**素材主要被当作参考使用，特效师看了之后自己再画贴图、不是直接下载来用**

### 2.5 不足

**魔法盒**
- 数据字段偏少（没看到文件格式、版本号、特效类型细分）
- 商业模型不清晰（抓取页面未发现付费入口）

**哔哩哔哩**
- 特效只是垂直话题，淹没在娱乐内容里（没有独立的特效分区，只能靠关键词搜）
- 搜索结果混入大量无关广告

**花瓣网**
- 整体偏通用设计，不是垂直的「游戏特效」站 —— 需要靠关键词与画板挖掘
- 搜索与发现机制对纯游戏特效不够友好

## 3. 结论：可复用范式与避开的坑

### 3.1 抄这些（已抓取验证）

1. **瀑布流布局** —— 来自魔法盒与花瓣网，适合「随便逛逛找参考」的场景
2. **视频作为主要展示形式** —— 来自 B 站与魔法盒；特效是动态的，视频最能还原真实效果
3. **三件套数据** —— 标题 + 作者 + 浏览 / 点赞 / 收藏（来自魔法盒）
4. **一键收藏** —— 来自花瓣网的「采集到画板」
5. **评论技术氛围** —— 来自魔法盒（专业讨论）

> 引擎分类（Unity / Unreal / AE）等用户可任意打的标签，统一通过搜索框查找（详见 5.1 第 3 项）。

### 3.2 不抄这些（避开的坑）

1. **靠搜索关键词做分类** —— B 站方式效率低，应做明确的分区
2. **不做特效制作环节** —— 画贴图只是特效制作流程中的一环（建模 / 贴图 / 绑定 / 引擎实现 / 调参 / 渲染……），本项目只覆盖「找参考」这一段

### 3.3 三个产品都没做好的机会点

1. **自定义标签**（用户自由打标签，不预设字典；魔法盒按引擎硬分类、B 站靠关键词、花瓣按通用设计分类——都没给用户自定义空间）—— 三家都没有
2. **自定义收藏夹**（用户按自己的需求命名和管理）—— 三家都没有
3. **跨平台索引 / 聚合**（花瓣网 + B 站 + 魔法盒统一索引）—— 目前没人做

## 4. 项目要解决什么问题

游戏特效师目前要在花瓣网、B 站、魔法盒等多个地方**找参考**：

- **花瓣网**：是特效师找参考的目的地之一（包含部分特效贴图），但埋在通用设计内容里
- **B 站**：特效成品**视频**很多，但搜索结果混入无关内容，靠关键词难以直达
- **魔法盒**：垂直的游戏特效参考，但规模有限

三处的内容互不相通，每个网站都缺少「特效类型」「来自哪个游戏」的统一标签，找参考要反复切换，效率低。**素材主要被当作视觉参考使用**——不是下载即用，而是看了受启发后，特效师自己回去画贴图、再到引擎里实现。

**VFXEffectHub 的核心价值**：把这三处的内容**统一索引**到一个地方，**按素材形态分区**——视频类内容主要来自 B 站与魔法盒，贴图类内容主要来自花瓣网；**标签完全自定义**（用户给任意作品打任意标签），通过**搜索框输入标签关键词**找到想要的参考；用户还可以为自己建**自定义收藏夹**管理内容。让特效师在一个网站内完成「找参考」全流程。本项目只覆盖「**找参考**」这一段，不涉及后续画贴图、引擎实现等制作环节。

> 本期 MVP 阶段由于技术门槛与版权风险，采用「手动收录 + 用户提交链接」的轻替代方案；自动爬虫与版权合规放到后续阶段。

## 5. 最小版本（21 天内能完成）

### 5.1 本期要做（MVP 阶段）

1. **素材形态分区**（顶层入口）：**视频参考区** / **贴图参考区** —— 用户进站选一个进；视频类内容主要来自 B 站与魔法盒，贴图类内容主要来自花瓣网
2. 瀑布流作品墙（每个分区首页的核心）
3. **搜索（基于标题 + 标签关键词）** —— **标签完全自定义**（用户写什么是什么是，不做预设字典）；在搜索框里输入「刀光」「鸣潮」「UE」等任意关键词，都能找到打过这些标签的作品
4. 三件套数据：标题 + 作者 + 浏览 / 点赞 / 收藏
5. 作品详情页：**视频区**展示视频播放器；**贴图区**展示大图；都含自定义标签 + **来源链接**（指向原页面）
6. **手动收录**：编辑者可把外链加进网站，**收录时不必填任何标签**（只填来源链接即可入库）
7. **自定义收藏夹**：用户可为自己建收藏夹（按需命名，比如「刀光参考」「鸣潮特效」），把感兴趣的作品收进同一处管理

### 5.2 本期不做（明确剔除，留给后续阶段）

1. **自动爬虫**（涉及版权 + 技术门槛，留到后续阶段）
2. **用户登录 / 注册**（多用户上传、评论都依赖它）
3. **用户提交素材**（依赖上一项）
4. **评论系统**（依赖用户登录）
5. **数据统计后台**

> **付费 / 商业化** —— 不在本项目范围内，作者明确不考虑。
