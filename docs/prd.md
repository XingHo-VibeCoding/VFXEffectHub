# PRD — VFXEffectHub（游戏特效素材参考收集网站）

> 本文档是 Vibe Coding 五步工作流第 3 步「写需求」的成果，以 `docs/research.md`（Day 3）为输入。  
> Day 7 起的 MVP 开发以本文档为准；技术选型在 Day 5 另行决定，本文只定「做什么、做到什么程度」。

---

## 1. 项目概述

**VFXEffectHub** 是一个面向游戏特效制作者的参考收集网站。它把分散在 B 站（视频）、魔法盒（视频）、花瓣网（贴图）等平台的游戏特效内容，通过手动收录的方式汇集到一个地方，帮助特效师在一个网站内完成「找参考」全流程。

**一句话定位**：为游戏特效制作者汇集分散的游戏特效素材；网站按 **Unity / UE / 贴图** 三大素材来源作为顶层入口（Unity、UE 分区只放视频类作品，贴图分区只放贴图类作品）；用户可叠加**二次筛选**（游戏名、特效类型，可选可不选）快速收敛结果；标签体系采用**预设 + 自定义**——预设覆盖常用游戏与引擎（详见 F6），用户可随时自定义新标签；用户还可以为自己建**自定义收藏夹**管理内容。

**重要边界**：素材主要被当作视觉参考使用——不是下载即用，而是看了受启发后自己回去画贴图。本项目只覆盖工作链路中「找参考」这一段，不涉及画贴图、引擎实现等制作环节。

**强制排除**：付费 / 商业化不在本项目范围内，作者明确不考虑，任何功能设计不得引入付费点。

## 2. 目标用户

**主要用户**：游戏特效制作者（特效师）

**用户场景**：

- 想看 UE 引擎的「刀光」参考 → 进 UE 分区，搜索「刀光」或在特效类型里选「刀光」
- 想看某款游戏（鸣潮）的特效 → 进 Unity 或 UE 分区，在游戏筛选里勾「鸣潮」
- 想逛贴图找灵感 → 进贴图分区瀑布流随便逛
- 找到好参考 → 收进自己建的「刀光参考」收藏夹，下次直接打开

**用户特点**：懂特效专业术语（刀光、序列帧、UE、顶点偏移……）；预设标签覆盖常用游戏名与引擎（详见 F6），其余由用户自定义；二次筛选的游戏名和特效类型下拉里，可选项也由编辑者按需添加。

## 3. 功能清单（MVP，共 7 项）

以下功能范围与 `research.md` 5.1 节基本一致；Day 4 多处重要修订（顶层分区改为 Unity / UE / 贴图、F3 加入二次筛选、F4 砍全站统计数字、F6 增加「来源类型 + 预设标签」机制），在各功能内单独标注，以本文档为准。

### F1 素材来源分区（顶层入口）

**做什么**：用户进站后从 **Unity / UE / 贴图** 三个分区中三选一进入；三个分区各自独立。

**做到什么程度**：

- 首页顶部有三个明确的分区入口，一眼能看懂区别
- **Unity、UE 分区只放视频类作品**（引擎实现的特效参考视频）；同一视频作品在收录时只能选 Unity 或 UE 之一，不会跨区
- **贴图分区只放贴图类作品**（静态图片素材）
- 分区切换随时可用（详情页除外——点进详情页说明用户正在看具体内容，无需切区入口）

**验收标准**：

- [ ] 打开网站首页，不用任何说明就能看到三个分区入口
- [ ] 点击任一入口能进入对应分区，且分区身份始终可见（知道自己现在在哪个区）
- [ ] 在浏览页面（瀑布流、搜索/筛选结果页），能一键跳到其他任意分区；详情页不提供分区切换入口
- [ ] Unity 与 UE 分区内容互不重叠（同一视频作品只属于一个引擎分区）

### F2 瀑布流作品墙（分区首页核心）

**做什么**：每个分区的首页是瀑布流作品墙，展示该分区的全部收录内容。

**做到什么程度**：

- 作品卡片包含：缩略图（Unity / UE 分区用视频封面图，贴图分区用贴图本身）+ 标题 + 作者
- 内容多时能滚动加载（或分页）
- 空数据时显示引导提示（而不是白屏或报错）

**验收标准**：

- [ ] 进入分区后能看到瀑布流布局，卡片排布整齐、无重叠
- [ ] 每张卡片至少显示缩略图、标题、作者三项
- [ ] 点击卡片能进入该作品的详情页（见 F5）
- [ ] 分区暂无收录时，页面显示明确的空状态提示文案

### F3 搜索与筛选（搜索框 + 二次筛选）

**做什么**：用户用搜索框输入关键词匹配标题或标签；同时可叠加二次筛选（游戏名、特效类型）进一步收敛结果。

**做到什么程度**：

- **搜索框**：标题、标签任一字段含关键词即命中（OR 逻辑，Day 4 拍板），限定在当前分区内
- **二次筛选**（叠加在搜索之上，可选可不选）：
  - **游戏名筛选**：下拉选择预设游戏标签（原神、鸣潮、绝区零、崩坏：星穹铁道……，可由编辑者按需新增）
  - **特效类型筛选**：下拉选择预设特效类型标签（具体预设值由编辑者按需添加，可全自定义）
  - 两个筛选可勾其一、可都勾、可都不勾；不勾时该维度不过滤
- 清空搜索词 / 重置筛选条件后回到当前分区完整的瀑布流
- 没有搜索/筛选结果时给出明确提示

**验收标准**：

- [ ] 输入已收录作品用过的标签词（如「刀光」），结果列表只出现标题或标签含这个词的作品
- [ ] 在二次筛选里勾选「鸣潮」，结果列表只出现标签含「鸣潮」的作品
- [ ] 同时输入搜索词 + 勾选二次筛选，结果需同时满足两个条件（搜索 ∩ 筛选）
- [ ] 输入没人用过的词，显示「没有找到相关结果」之类的提示，不白屏不报错
- [ ] 清空搜索词和筛选条件后回到完整的瀑布流
- [ ] 搜索和筛选结果都限定在当前分区（在 UE 分区搜，Unity 分区的内容不会出现）

### F4 数据展示（标题 + 作者 + 点赞/收藏状态）

**做什么**：每个作品展示标题、作者；点赞与收藏以「状态」呈现（已赞 / 未赞、已收藏 / 未收藏）。

**做到什么程度**：

- 卡片上显示标题 + 作者（见 F2）；详情页显示标题、作者 + 点赞、收藏两个可点击的状态按钮
- 点赞、收藏状态保存在用户本地浏览器（本期无登录，数据不跨设备；升级路径见第 6 节）
- **收藏（红心）与收藏夹的联动规则**见 F7（Day 7 开发期拍板：进夹即收藏 / 取消收藏即移出所有夹 / 点红心自动入默认夹）
- **本期不做「浏览数 / 点赞数 / 收藏数」这类全站统计数字**：共享计数需要服务器，超出本期范围（与 research.md 5.1 的差异在此，以本文档为准）

**验收标准**：

- [ ] 详情页能看到标题、作者，以及点赞、收藏两个可点击按钮
- [ ] 点赞 / 收藏点击后按钮状态可见变化（如点亮 / 取消），刷新页面后状态保留
- [ ] 详情页不出现「浏览数 / 点赞数 / 收藏数」等全站统计数字

### F5 作品详情页

**做什么**：展示单个作品的完整信息。

**做到什么程度**：

- Unity / UE 分区：展示视频内容（内嵌播放或封面引导）；贴图分区：展示大图
- 展示该作品的全部自定义标签
- 提供**来源链接**，点击后跳转到原页面（B 站 / 魔法盒 / 花瓣网原网址）
- 提供收藏入口（收进收藏夹，见 F7）

**验收标准**：

- [ ] Unity / UE 分区的详情页能看到视频内容，贴图分区的详情页能看到大图
- [ ] 作品的所有标签可见
- [ ] 点击来源链接能在新标签页打开原始网址
- [ ] 页面上有收藏按钮，点击后能把作品加入某个收藏夹

### F6 手动收录

**做什么**：编辑者（作者本人）把外部作品链接加进网站。

**做到什么程度**：

- **必填四项：来源链接、来源类型（Unity / UE / 贴图）、标题**；标签选填（想让它能被搜到或被二次筛选命中就填，不填也能正常展示）
- **来源类型**（三选一：Unity / UE / 贴图）——决定作品进入哪个顶层分区；视频类作品的引擎归属在收录时固定，同一作品不会同时属于 Unity 和 UE
- **标签体系（预设 + 自定义）**：
  - **预设标签**（Day 4 用户拍板起点列表，编辑者可按需新增/调整）：
    - 游戏：原神、鸣潮、绝区零、崩坏：星穹铁道
    - 引擎/形态：Unity、UE、贴图
    - 特效类型：暂未预设，按需添加
  - **自定义标签**：用户可随时输入新标签，无需审核直接生效
  - 收录界面提供预设标签的可视选择（如点选/下拉），同时允许输入自定义
- **视频类收录**（来源类型为 Unity 或 UE）：可选填封面图链接（右键 →「复制图片地址」）。B 站图片已实测可外嵌显示（需站内配合 no-referrer 配置，Day 7 落实）；不填则用默认占位图
- **贴图类收录**（来源类型为贴图）：必须上传图片文件（在原页面右键 →「图片另存为」存到本地，再上传进本项目）。已实测花瓣网图片地址带**短时效签名（当天过期）**，外嵌必然裂图，故贴图一律存文件；图片在本项目内，显示最稳
- **收录原则：一律只使用免费显示的预览图**（原页面右键「图片另存为」得到的版本），不购买、不获取任何付费原图 / 付费下载内容。Day 4 用户实测补充：花瓣**付费图的预览图同样可以右键另存**，因此收录范围不受「原图是否收费」影响——找参考所需的清晰度，预览版已足够，且不触碰作者的付费权益
- 收录入口不对公众开放（无注册功能，见「本期不做」）
- 录入作者信息

**验收标准**：

- [ ] 只填必填项（链接 + 来源类型 + 标题，贴图再上传图片文件），不填任何标签，能成功收录且作品出现在对应分区
- [ ] 收录时填了标签（如「刀光」「鸣潮」），之后搜索这些词能找到该作品
- [ ] 收录来源类型为 Unity 的视频只出现在 Unity 分区；UE 同理；贴图只出现在贴图分区
- [ ] 同一视频作品在收录时只能选一个引擎分区（不会同时出现在 Unity 和 UE）
- [ ] 收录界面提供预设标签的快速选择（如点选预设 + 输入框补自定义）
- [ ] 贴图作品在瀑布流里显示的图就是收录时上传的那张图片文件

### F7 自定义收藏夹

**做什么**：用户为自己建收藏夹（按需命名，如「刀光参考」「鸣潮特效」），把作品收进同一处管理。

**做到什么程度**：

- 可创建多个收藏夹，名字完全自定义
- 可把任意作品加入任意收藏夹；能查看每个收藏夹内的作品列表
- **默认收藏夹**（Day 7 开发期拍板）：首次使用时自动创建一个「默认收藏夹」；点红心收藏而不指定夹时，作品自动进入默认夹；用户删除默认夹后不会自动重建
- **收藏联动规则**（Day 7 开发期拍板，红心与收藏夹成员保持强同步）：
  - 加入任意收藏夹 → 红心自动点亮（进夹即收藏）
  - 取消红心 → 作品自动从所有收藏夹移除（并提示从几个夹移除）
  - 点红心而不选夹 → 自动落入默认收藏夹
  - 心智模型：红心亮 = 作品被收藏（在某夹中）；红心灭 = 不在任何夹中
- **无需注册登录即可使用**：收藏夹数据保存在用户本地浏览器（类似浏览器书签）——**换电脑或清浏览器缓存后数据不保留**
- 数据跨设备保留需要「登录 + 服务器数据库」，工程量超出本周期范围，列为日后升级项（见第 6 节）

**验收标准**：

- [ ] 能新建收藏夹并自定义命名
- [ ] 能把一个作品加入收藏夹，之后在收藏夹里能看到它
- [ ] 能同时存在多个收藏夹，内容互不混淆
- [ ] 不经过任何注册 / 登录步骤就能完成上述操作
- [ ] 首次使用即存在「默认收藏夹」；点红心（不选夹）后作品出现在默认夹中（Day 7 新增）
- [ ] 加入收藏夹后红心点亮；取消红心后作品从所有收藏夹消失（Day 7 新增）

## 4. 总体验收标准（Day 7 起逐条对照打勾）

1. 打开网站能完成完整闭环：**进站选分区 → 逛瀑布流 → 搜索「刀光」→ 打开详情页 → 点来源链接 → 收进收藏夹**，全程不报错
2. 三个分区（**Unity / UE / 贴图**）各自独立，内容不会串区
3. 搜索命中标题和标签，空结果有提示
4. 收录不带标签的作品能正常入库和展示
5. 收藏夹无需登录即可使用
6. 全站无任何付费入口、付费提示
7. 点赞、收藏的操作有可见的状态反馈；全站不出现「浏览数 / 点赞数 / 收藏数」等共享统计数字
8. 上线前每个分区（Unity / UE / 贴图）至少预收录 **5 条**真实内容（Day 4 拍板：解决空站冷启动，预收录由作者用 F6 手动完成；3 个分区合计 **15 条**，Day 7 减半修订——保证最低密度门槛与收录速度的可比）
9. 二次筛选（游戏名 / 特效类型）可勾可不勾，不勾也能正常浏览瀑布流

## 5. 本期不做（明确剔除，与 research.md 一致）

1. **自动爬虫**（版权 + 技术门槛，留到后续阶段）

4. **评论系统**（依赖用户登录）
